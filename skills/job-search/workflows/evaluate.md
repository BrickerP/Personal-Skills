# Evaluate and shortlist jobs

Use for “is this a fit?”, comparing postings, or ordering a candidate pool.
Evaluation is a reasoned recommendation, not permission to submit.

## Inputs

Read the actual posting, the relevant profile/experience evidence, and the
user's target preferences via [shared sources](../references/shared-state.md).
For an existing application, use the archived JD when it exists and identify
that version. If only a title or snippet is available, label the assessment
provisional and obtain the description before a substantive recommendation.

## Assess in context

- **Eligibility and constraints:** check the posting's stated location, working
  arrangement, clearance, authorization and language requirements against known
  facts. Quote a material mismatch. Use the existing approved answers; do not
  invent citizenship, experience, dates, relocation or sponsorship facts.
- **Skills and experience:** identify supported requirements, adjacent experience
  and genuine gaps. Match the work performed, not just historical job titles.
- **Career direction:** explain whether the work advances the user's goals and
  which projects or achievements provide the strongest evidence.
- **Practical application cost:** note missing materials, unknown required
  questions, a stale posting or a likely ManualFinish gate. A portal classified
  as easy by a helper can still present different questions on the live page.
- **Evidence quality:** company claims should come from a verifiable source.
  Distinguish a posting statement, independently verified fact and inference.

Keep hard constraints separate from preference gaps. Do not quietly discard a
posting because one preferred tool is absent or its fit is not perfect. If an
important fact is unknown, say what would resolve it rather than filling it in.

## Match the requested search mode

For a targeted/referral role, prioritize depth: strongest evidence, gaps to
address, application angle and whether tailored material is worthwhile.

For the existing daily-50 routine, retain the broad eligible software funnel and
the required Agent / AI Infra / ML Systems seed lane. Prioritize useful roles
within the existing zero-gate Greenhouse queue. Do not add a new numerical
threshold or remove reasonable Backend/Full-stack/Platform roles solely to
improve a synthetic fit score. Company blocks, dedupe and current form policy
still govern whether a role can proceed.

## Output and handoff

Return a short recommendation per role with:

- strongest supported matches;
- material gaps or unresolved constraints;
- priority and the reason for it;
- the next useful action: pursue, investigate, defer or skip.

Use [resume](resume.md) for selecting/updating the CV and [materials](materials.md)
for role-specific writing when needed. An authorized volume run can proceed to
[apply](apply.md) with the existing curated PDF. Do not create application
tracker entries or claim that anything was submitted merely from evaluation.
