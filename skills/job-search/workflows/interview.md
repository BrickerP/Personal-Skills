# Prepare for an interview

Use for a scheduled or prospective interview, a mock interview, or debriefing
a completed round. Enter here directly; no new search or application is needed.

## Load the relevant application

Read the company, role/JD and interview stage from the user's request and
[existing records](../references/shared-state.md). Ask for the date, format,
round or interviewer only when it is missing and useful for preparation.
If several roles at the same company exist, resolve the specific requisition.

Prefer the archived JD and actual submitted resume/materials. Identify missing
artifacts explicitly: a current PDF is not proof of the version the employer
read. Use the current resume as a clearly labelled fallback when necessary.
Previous-round questions and feedback are the most relevant input for the next
round; keep them separate from a fresh prep document.

## Build the preparation

- Research the employer's public work and the interviewer's public professional
  role when known. Verify company claims before making them talking points.
  Do not start LinkedIn actions while frozen; use accessible public sources.
- Map the JD to likely technical and behavioral questions. Give previous-round
  concerns priority over generic question lists.
- Select STAR stories from sourced experience. Missing result metrics stay
  missing until confirmed; prepare an honest bridge for an experience gap.
- For technical rounds, use the user's actual systems and project evidence to
  prepare design choices, failure modes, tradeoffs and ownership depth.
- Build a consistency brief for the submitted CV's strongest numbers, decisions
  and scope claims. Prepare to defend the claims actually on the paper.
- Prepare relevant questions for the interviewer and practical logistics. Use
  the approved authorization/compensation facts; unknown preferences need the
  user's decision rather than an invented answer.

## Practice and feedback

When mock practice is requested, conduct it in the conversation, one question
at a time. After an answer, give specific feedback on evidence, clarity and
technical depth; adapt the next question to the actual response.

For a debrief, record what the user reports happened, questions asked, uncertain
answers and the next agreed step. Distinguish employer feedback from the user's
impression and the agent's inference. Never invent interviewer conclusions.

## Output and handoff

Use the existing Vault layouts: `Interviews/<Company>.md` for a small process,
or `Interviews/<Company>/` with `jd.md`, `prep.md`, `questions.md`, `feedback.md`
and optional `meta.yaml` when multiple rounds justify it. Preserve existing
content and dates; do not create a second interview tracking system.

Deliver a stage-specific prep pack, practice feedback or debrief as requested.
Use [review](review.md) to reconcile an actual stage update with the tracker.
Preparing a pack does not itself advance the application stage, contact the
employer, accept an offer, or schedule a meeting.
