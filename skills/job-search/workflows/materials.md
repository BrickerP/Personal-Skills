# Prepare application materials

Use for a cover letter, motivation answer, project description, introduction or
other role-specific application text. The output is reviewable material; this
stage does not upload, submit, send or publish it.

## Inputs

Read the question exactly as asked, its word/character limit, the posting and
the relevant [shared facts](../references/shared-state.md). Use the selected
resume as the consistency reference. Ask for a missing question or material
fact that changes the answer; do not fill an unknown with a plausible story.

## Draft with evidence

1. Identify the employer's stated problem and select the strongest supported
   experience that speaks to it. Address real gaps honestly with adjacent work.
2. Keep employer-specific claims grounded in independently checked sources.
   A reviewer or search snippet is not independent verification on its own.
3. Draft in the user's established voice with concrete work and outcomes. Scope
   contribution accurately; an application answer cannot quietly broaden what
   the resume says the candidate owned.
4. Review against the question, actual evidence and selected resume. For a
   substantive targeted application, use a fresh reviewer when available; pass
   only the necessary material and request critique rather than file mutations.
5. Revise and check names, dates, numbers, claims, tone and length. Measure
   hard word/character limits rather than estimating them.

Follow the [outbound content policy](../../daily-job-apply/guards/stealth-rules.md).
Use real approved employer names while protecting non-public internal specifics.
Personal drafts belong in the user's existing private application/Vault location,
not this skill repository. Describe which file is a draft and which, if any,
was actually submitted; retain earlier submitted versions.

## Preserve form-policy boundaries

The [FROZEN answers and ManualFinish policy](../../daily-job-apply/workflows/04-universal-web-apply.md)
still govern live forms. Generating an ordinary draft does not unlock required
essays, salary expectations, legal attestations or other unresolved questions
for unattended daily-50 submission. Prepare requested text for user review and
leave any corresponding submission gate unresolved until the user supplies
the relevant decision under the existing policy.

An employer instruction forbidding AI assistance, an AI-usage attestation or
anti-AI challenge remains ManualFinish. Do not answer the challenge, disguise
AI involvement, or manufacture an “own work” declaration to pass a gate.

## Output and handoff

Deliver the material with its intended field/employer, measured count when
limited, evidence gaps needing review, and the selected resume version. For
file output, use the existing application folder or the user's requested path.

Use [resume](resume.md) when the CV itself needs an authorized revision.
Use [apply](apply.md) only for a separately authorized submission. The end of
this stage is material ready for review, not `Submitted` in the tracker.
