# Job search setup for another user

Install the current `BrickerP/Personal-Skills` repository and run its
`scripts/install.sh`. Start with [job-search](../job-search/SKILL.md); it routes
to a Markdown workflow for searching, screening, resumes, application materials,
applying, interview preparation or review.

Keep `job-search` and `daily-job-apply` installed together. A historical zip with
only the old daily skill does not contain the new lifecycle entry. See
[INSTALL.md](INSTALL.md) for requirements and preserving an existing install.

Before applying, supply your own local profile, approved field answers,
Chrome identity, resume artifacts and hash baseline. Do not use the original
author's FROZEN facts. Your phone values stay only in local environment config;
never put private contact information, tracker rows or application archives in
the public skill repository.

The browser workflow is agent-driven: inspect the live page, decide, operate
and verify one role at a time. Helpers may source public job data, deduplicate,
inspect or record; they do not fill forms or submit applications. There are no
Node/Playwright adapter dependencies to install for that workflow.

`daily-50` is the original user's application preset, not a default volume or
permission for another user. LinkedIn remains frozen in the shipped policy.
The legacy names route to the same lifecycle workflow and do not create
additional application engines.
